# Build conventions (read before writing any page)

Stack: Next.js 16 app router (src/app), React 19, Tailwind v4 with CSS variables from src/app/globals.css. `cacheComponents` is OFF; every data page exports `export const dynamic = "force-dynamic";`. Fonts load via a <link> in layout (no next/font). `PageProps<"/route">` and `LayoutProps` are globally available types (searchParams is a Promise).

Shared pieces: `src/components/ui.tsx` (Banner, Chip, Card [class "card"], H1), `src/components/Nav.tsx` (Today | Ask | Tasks | Money | More), `QuickBar` (Ask input + "+"), `AppearanceProvider` + `src/lib/appearance.ts` (F8.A). Use `card` class for every card so Appearance (card style, density, radius) applies. Status colors: classes `text-green/bg-green-bg`, `text-amber/bg-amber-bg`, `text-red/bg-red-bg`; never recolor statuses.

Data: `src/lib/data.ts` holds v1 readers with sample fallbacks when Supabase env is unset (`hasSupabaseEnv()`). Each slice adds ITS OWN file `src/lib/data-<slice>.ts` with the same pattern (types, sample data, readers that fall back to samples), and ITS OWN migration `supabase/migrations/000N_<slice>.sql` (tables + RLS: members read via `public.is_member()`; browser writes only where the requirements allow; service role for the mini agent). Do NOT edit data.ts, Nav.tsx, layout.tsx, globals.css, ui.tsx or another slice's files; add new files. The /more hub page lists every secondary page; if your slice adds pages, add them to `src/lib/more-links.ts` ONLY by appending entries to the array section marked for your slice.

Rules from docs/requirements.md that every page must follow: phone first (max-w-md main), "needs me" at the top, at most 5 items then "and N more", every card has an "Open in …" link to its source (href can be "#" with the source named), Sync status + "Sync now" on anything synced, nothing sensitive (no numbers beyond last-4, no contents), three confirmation tiers (tier 1 saves with Undo toast; tier 2 one-line confirm card; tier 3 explicit confirm button), sample content only (bracketed placeholders like [Child 1], $[PRICE] where real values are unknown; Ryan, Melissa, Tahoe, Sienna are real names and fine).

AI calls: all go through `src/lib/ai.ts` (to be created by the Ask slice): `callModel({ job, messages })` routes by job to haiku/sonnet/opus per F18, uses `ANTHROPIC_API_KEY` if set, otherwise returns a deterministic sample reply tagged `{ sample: true }`. Other slices import it; never call the API directly.

## Agents on the hub (added 2026-10-29, decision D34)

**Every agent on the hub is installed by the kit, never by hand.** An agent is one entry in `MODULES` in `scripts/hub.mjs` (id, script, how often or always-on, the prerequisite that switches it on, what it powers). `node scripts/hub.mjs` is the doctor's report; `--apply` writes and loads the launchd job of every module whose prerequisite exists on that Mac — the setup wizard runs it on a customer's machine, Ryan runs it on his. Adding an agent means adding a `MODULES` entry and nothing else; there are no hand-written plists in the repo any more. An agent that is not a module is not in the product, and only agents we want permanently go in. Household-specific arguments (a mailbox address, say) are derived from the sign-ins present on the hub, never written into the module. Labels are `com.stewardos.<id>`; logs are in `~/StewardOS/logs/`. Ryan's own jobs (`dashboard-report` until the reporter is rewritten, `bookmark-evening`, `publish-materials`) are listed as personal and left alone.

## Model reliability log (added 2026-10-24, migration 0043/0044)
- Every model call goes through `callModel` / `callModelVision` in `src/lib/ai.ts` and writes one `ai_usage` row, now with `latency_ms`, `runtime` (cloud or local), `prompt_version`, `valid_output`, `subject_kind` and `subject_id`.
- Pass `subject` (the thing the call was about), `promptVersion` and `validate` (for example `jsonObjectValid`) on any call whose result a person will act on. Validity is judged before the row is written because the log is append-only.
- Bump `promptVersion` by hand whenever the prompt text changes, so scores are never mixed across prompts.
- Record what the person did with the result in `ai_outcomes` through `src/lib/ai-outcomes.ts` (`recordOutcome`, `recordFilingOutcome`): accepted, edited (field names only) or rejected. Never update or delete outcome rows.
- `model_scorecard` (view) is the per-job, per-model, per-prompt-version summary. Switch a job to a different or local model only after the new model is replayed against past results and matches or beats the current one; log the decision in the decisions log.
- Telemetry that leaves a household is shape only and opt-in: counts, rates, latency, field names. Never values or documents.
