# Dashboard Requirements and Layout (living doc, started 2026-10-17)

Purpose: the single place where everything the dashboard should include is collected, then laid out by priority and usability. Ryan describes the ideal features and how he will use them, in any order and any wording; Claude files each one here, merges duplicates, and keeps the layout coherent. Design comes first, build later (see claude/dashboard-v1-design.md for the technical design of the first slice, claude/family-dashboard-plan.md for the original plan, claude/ongoing-ingestion-plan.md for the Inbox/action queue, claude/email-plan.md, claude/spending-monitor-plan.md and claude/subscriptions-plan.md for the earlier email and money thinking, claude/responsibilities-and-reports-plan.md for the daily report idea, claude/family-file-access-plan.md and claude/important-documents-plan.md for family documents).

## Design principles (apply to every screen)
- Clean, and segmented per person (Ryan, 2026-10-18, first principle): every screen shows only what is relevant to the person looking at it, grouped so it is understood at a glance. Nothing shared, system-level or someone else's appears on a person's working pages unless they chose it. Reference material, registers and settings live off the working pages (Settings and Info) and are reached by link, never by scrolling past them. A new section earns a place on a working page only if someone needs it most days; otherwise it is a register under Info with a reminder that surfaces when due. When in doubt, hide it and link to it.
- Always say who (Ryan, 2026-10-18): every item, everywhere, names the person who asked for it or whom it is for, next to where it came from: "Melissa asked · from Messages · 7:52", "For [Child 1] · from school email". System-generated items say "System · from email (Ryan's Gmail)" so the account is still named. Applies to tasks, Y/N confirmations, questions, records, cart items, checklist edits, settings changes and log lines; never just the source.
- Usable by anyone, with no training: plain words, one clear thing per screen, big tap targets, works on a phone first.
- "Needs me" first: the top of every page answers "what needs me right now?" Everything else is secondary. Silence means healthy.
- One place for actions: every approve/decide/acknowledge happens here, not in Finder, email or chat.
- A view, not a source of truth: the files, sheets, calendar and Project docs stay the source.
- Nothing sensitive shown: no passwords, account or ID numbers, file contents. Links only, opened behind the owner's own unlock.
- Each person sees only their own items plus shared ones; children see only what parents allow.
- Consistent layout: same navigation on every page, same item card, same colors for the same meaning (green ok, amber needs attention, red problem).
- Accessible: readable text sizes, high contrast, light and dark, keyboard and screen-reader friendly.
- Nothing leaves the house without a person: drafts are never sent automatically; a task is the unit of work, and every task shows where it came from.
- Every item reaches "resolved": an item stays on the list, asking for exactly what is missing, until it is recorded and filed in its proper place. The list is never cleared by time passing.
- Capture anywhere: a camera button and an upload button are on every item that needs a document, and a general drop zone takes anything in bulk.
- Confident or ask: the system acts on its own only when confident; otherwise it asks one short question on the dashboard. Every answer becomes a rule, so questions get rarer over time. The person is never asked the same thing twice.
- Private by default: location and activity records belong to the person they are about; they are visible only on that person's page and never shared with others (including other family members) unless that person turns sharing on.
- Ask in plain words, anywhere: a question box is on every page. Whatever the family knows (schedules, documents, people, places, money, history) can be asked for in one sentence and answered or delivered there. The same box takes instructions: "add", "change", "turn off" are placed in the right setting or register automatically, confirmed with one tap, and recorded as the source.
- One queue, one morning: everything that needs a person is one ranked queue shown in views (Today, Money, Family), never duplicated; and all scheduled notifications merge into one morning summary per person, with a weekly review and immediate alerts only for safety and money thresholds.
- Three confirmation tiers: low-risk changes save at once with Undo; medium ones show a one-line card; high ones (money set-up, access, another person's data) require confirmation and, where the Change Log says so, both parents.
- Useful, never annoying: notifications are few, timed to when they help, and each one says something the person can act on. The same fact is never pushed twice. Everything pushed is also quietly on Today, so missing a notification costs nothing.
- Edit in place, learn from edits: anything the system generates (a checklist, a tag, a rule, a filled gap) can be changed where it appears with one tap, and the change teaches the system for next time.
- Two vaults, fixed roles (Ryan, 2026-10-18): passwords live in Apple Passwords (personal, plus shared password groups for anything both parents manage). Sensitive documents (IDs, insurance cards, vehicle registrations, titles, cards, policies) live in 1Password, so the dashboard can point to them and deliver a link. The dashboard stores neither; it stores only the item name and which vault, and every "deliver" opens the vault behind the person's own unlock.
- Go deeper in one tap (Ryan, 2026-10-18): everything shown here came from somewhere, and every card carries an "Open in …" link to that exact thing in its source, with a Sources page listing every source as a button. The dashboard is the front; the sources stay one tap away.
- Sync on demand (Ryan, 2026-10-18): anything that syncs shows when it last synced and has a Sync now button, so a stale view is fixed by the person in one tap, never waited out.
- Money is recorded, never moved: the dashboard reads, matches, files and reminds. Paying, transferring, cancelling and disputing happen outside it, by a person, from a prepared task.

## Priority tiers (how the content is ordered)
Tier 1, the home screen ("Today"): the morning schedule (calendar windows plus filled gaps, with weather and a checklist on each block), what needs me now (tasks, money asks, schedule questions), alerts, system health in one line, and the Ask box.
Tier 2, daily use: Ask (the assistant window), Tasks (from email and elsewhere), Money (Needs me, status strip, this month, accounts, reconciliations), Inbox items to file/decide, Calendar and trips (with weather on every future event), the Day record (what was done, learned from calendar and location).
Tier 3, regular reference: Family (one page per member with everything that relates to them, including their activities, checklists, devices and their own private health section), Vehicles (one card per vehicle, managed by its driver), Recurring and renewals (the register, shared with Money), Documents finder, Reports and tax, Source register, Events log, Places (learned locations and what they mean).
Tier 4, occasional: Settings and Info (F8: people and access, connections, notifications, money set-up, schedule and activities, filing, look and feel, My dashboard, data and privacy; plus the read-only Info pages: how it works, status and health, Sources (F14: a Go button and a Sync now button for every place data comes from), household reference, devices and belongings register (F10), home and property (F12.1), contacts (F12.9), emergency and continuity plan (F12.5), where things live, logs). Changed less than monthly, so kept off the working pages.

## Candidate navigation (to refine with Ryan)
Today | Ask | Tasks | Money | Family | Vehicles | Messages | Inbox | Calendar | Recurring | Documents | Log | Settings and Info (Systems/health, Sources and the source register live under Info)
A persistent "+" button on every page: Take photo / Upload file / Bulk drop. A persistent Ask box on every page. Children's logins land on their own simple page instead of this menu.

## Features (Ryan's description, then how it lays out)

### F1. Email handled for me (Ryan, 2026-10-17)
In Ryan's words: "I want you to manage all my email. I don't want to ever look at email. Read it, deal with attachments, and deal with email in any manner needed so that I only get tasks or communications that need a response. Any communication that comes through email becomes a list of tasks, with where the communication originated. If an email needs a response, draft the reply and put a link to it on the dashboard next to the task, so it can be opened and edited or sent as drafted. If attachments are required and you have access to them, attach them before presenting the draft. If you don't have access or can't figure it out, make sure it doesn't get sent without the required attachment."

How it lays out:
- Email never appears as email. It appears as tasks in the Tasks list (and the top of Today when due or urgent). Each task card shows: what needs doing, who it came from (sender, account, date, subject as a label), a one-line summary, due date if any, and the action buttons.
- Task types from email: Reply needed (draft attached), Do something (pay, sign, book, send a file), Decide (yes/no or pick one), Just so you know (read-only, auto-expires), Nothing needed (handled silently: filed, unsubscribed, archived; visible only in the Log).
- Reply tasks (updated 2026-10-18, Ryan confirmed F15 item 4): the draft lives in the dashboard first. "Open draft" opens an in-dashboard preview with inline editing; the mail draft is created in the mail app only when every needed attachment is present (or the person taps "Create anyway, I'll attach it myself", which is logged). "Send" then opens the finished draft in the mail app for the final send. The dashboard never sends.
- Attachments: the task shows a checklist of attachments the reply needs. Each is Attached (found and added), or Missing (with where Claude looked). A reply with a Missing item is marked "Not ready to send" and no mail draft exists yet, so it cannot be sent by mistake; the task offers "Find it for me" (opens the Documents finder) or "Attach from my phone".
- Attachments received: bills, statements, receipts, tax and legal documents are filed automatically (Inbox filing rules) and the task notes where they went; anything uncertain becomes an Inbox item.
- Cost control, the free funnel first (Ryan, 2026-10-18): a model is never used on junk or marketing. Stage 1, provider filters: anything in Spam, Junk, Promotions or Social is skipped and only counted. Stage 2, fixed signals from headers: List-Unsubscribe, bulk precedence, no-reply and known automated senders (receipts, statements, shipping, calendar invites, codes) are filed or archived by rule; receipts and statements go to the Money pipeline. Stage 3, the family's own rules, matched by sender and domain. Only mail that survives all three (a new human or company) goes to Haiku for triage, with subject, sender and the first part of the body, never attachments. Cold start: before go-live, the last 90 days of each mailbox are scanned by the free stages only and sender rules are proposed in one batch for one-tap approval. A daily cap on triage calls per account exists in Settings but ships off (Ryan, 2026-10-18); when on, overflow falls back to rule-only mode with a note in the weekly review.
- Handling rules grow from Ryan's choices: every "ignore this sender", "always file these", "this is spam" becomes a rule proposed for one-tap approval (same mechanism as file-filing rules).
- Both parents: Melissa's mail works the same way on her page, with her approval of the setup.
- Trust and audit: the Log keeps one line per email handled (what was done, which rule), so "did you deal with X?" is answerable in one search. Nothing is deleted; archived only.
- Accounts in scope to confirm: iCloud mail (Ryan), the Google business accounts (admin@shvr.co, admin@medrepdesk.io), rross15253@gmail.com, Melissa's. Each is a row in the source register.

Open questions for F1: which accounts first; how often to check (continuous vs a few times a day); whether some senders (family, key clients) should notify immediately; whether Ryan wants a daily digest as well as the live list.

### F2. Receipts reconciled, every expense explained (Ryan, 2026-10-17)
In Ryan's words: "Because you will be managing my statements and credit card charges, expenses and so forth, I want you to reconcile as many receipts as possible. The first search for them will be email, because I will try to have all receipts and paid bills sent to email. If it can't be found in email, notify me on the dashboard that we are missing receipts or detail of the expenses. I want a camera button where a picture of a receipt can be taken, and an upload button so a scan can be uploaded for a specific item. I also want a way to bulk upload financial items into a general financial inbox; when items are dropped there you automatically try to deal with them, and if you can't, ask for more info on the dashboard per item until every item is resolved, recorded and filed in its proper location."

How it lays out (the receipt loop; the full Money section is F7):
- Reconciliation loop, automatic: every charge or statement line (bank, credit card) is matched to a receipt or bill. Search order: 1) email (receipts and paid bills, all accounts in scope), 2) already-filed documents in Organized, 3) the financial inbox (bulk drops). Matches by amount, date window, merchant; recurring charges match their subscription or bill record. A matched item is recorded (date, merchant, amount, category, account, where the receipt is filed) and the receipt is filed to Finance/<year>/<category> (statements to Finance/Statements). Match confidence is shown; low-confidence matches are confirmed by a tap, not assumed.
- Missing: a charge with no receipt or no detail becomes a "Missing receipt" item on Money (and Today if older than a few days). The card shows merchant, amount, date, account, what was searched, and three buttons: Camera (take a photo of the paper receipt now), Upload (a scan or PDF from the phone or computer), and Explain (a short note such as "cash tip, no receipt", "personal, not business", "split with X"). Any of the three resolves the item once it is recorded and filed.
- Per-item capture: Camera and Upload attach to that specific charge, so the match is certain. The photo or file is filed with the record; the dashboard keeps only a thumbnail and a link.
- Financial inbox (bulk): a general drop zone (the "+" button on every page, plus a drag-and-drop area on Money and a mail-in address or shared folder for scans) takes anything: photos, PDFs, statements, invoices, a shoebox of receipts scanned in one go. Each dropped item is processed automatically: read (OCR), identified (receipt, bill, statement, invoice, other), matched to a charge if one exists, recorded and filed. Items that cannot be fully handled become per-item asks on the dashboard, each stating exactly what is missing (which account, which charge, is this business or personal, what category, is this a duplicate). The ask repeats until the item is resolved; nothing is dropped or auto-deleted. A progress line shows "12 of 15 resolved".
- Both directions: a receipt with no charge yet waits as "Expecting a charge" and matches when the statement arrives; a receipt whose charge never shows after a set time becomes an ask ("was this paid another way?").
- Business and personal: each item is tagged to a business (Veil Labs, a venture, SHVR, etc.) or Personal; rules learn merchants per business; the record feeds the tax folder for that year and that entity.
- Rules learn: every answer to an ask ("this merchant is always SHVR, category Materials") becomes a proposed rule for one-tap approval, so repeats are handled without asking.
- Feeds other features: missing-receipt counts on Today; subscription and bill records on Recurring; statements and receipts in the Documents finder; one Log line per item. Location (F3) helps matching: a charge at a merchant near where the person was at that time is a stronger match, and a receipt photo taken at a place is tied to that visit.

Open questions for F2: how long to wait before a charge is flagged as missing (suggest 5 days); whether to keep paper receipts after scanning. (Accounts, cards and statement delivery are in F7.)

### F3. Morning schedule, and a complete record of the day (Ryan, 2026-10-17)
In Ryan's words: "I want a daily schedule every morning with time windows grabbed from the user's connected calendar. I would also like a GPS connection: if there are gaps in the schedule that aren't on the calendar, the GPS shows where the user was, and you learn which locations tie to which activities over time. If you are confident, you add them to the filled schedule so there is a record of everything that was done. If confidence is low, I want a list of questions on the dashboard that need to be answered so that you can learn over time."

How it lays out:
- Morning schedule (top of Today, ready before the person wakes): one timeline for the day, built from every connected calendar for that person (and shared family calendars). Each block shows time window, title, place, travel time to the next place, the weather for that block (F5), and its checklist (F6: documents, tasks due before it, clothing or gear). Free windows are shown as gaps, not hidden, so the day reads as a whole. Delivered as a notification at a chosen time (e.g. 6:30) and always on Today; also readable aloud or as a short text.
- Day record (the same timeline, looking back): as the day happens, the calendar blocks are kept, and the gaps are filled from location. The phone's location history (shared with the dashboard by that person, on their own phone, with a clear on/off switch) gives "where" and "how long"; the system turns that into "what": home, office, gym, a client's address, a store, school pickup, the kids' activities. Yesterday's record is complete on Today each morning, under the schedule.
- Learning places: each stopped-at location becomes a Place (coordinates plus a name and a meaning: "Home", "SHVR workshop", "Costco, Orem", "Dentist"). Places are learned from calendar matches (a calendar event at that time and spot names the place), from receipts and charges (F2: a charge at a merchant at that time), from contacts' addresses, from map lookups, and from the person's own answers. Over time each Place carries its usual activity, usual duration and usual days, so repeat visits are filled in without asking. Each Place also learns whether it is indoors or outdoors (feeds F5).
- Confidence rules: a gap is filled automatically only when the Place is known and the usual activity fits (right time of day, right duration, right day of week). Automatic fills are marked "inferred" (a small icon) so the person can correct them with one tap. Anything else becomes a question.
- Questions (the learning loop): a short list on Today, "Yesterday: 3 questions", each one tap to answer: "2:10 to 3:40 pm at 540 W Center St, Orem. What was this?" with suggested answers (the nearest Place, recent similar visits, "personal", "skip"). Answering names the Place and the activity; the answer becomes a rule for next time. If the person doesn't answer, the question stays on the list a few days, then folds into the weekly review, never deleted. The person is never asked twice about the same Place and pattern.
- What the record is for: a true log of the day (for memory, for "when did I last visit X", for mileage and travel records, for business vs personal time, for the tax folder when a trip is business), and a feed for other features: travel time warnings on the morning schedule, receipts expected after a store visit (F2), tasks tied to a place ("drop off forms" surfaces when near the school).
- Privacy and control: location is collected on the person's own phone and shared only to their own dashboard page. Each person turns it on or off, can pause it (a "private time" switch that leaves a gap on purpose, with no question asked), can delete any day's location record, and can decide whether other family members see their day at all (default: no). Children's location, if ever used, is a parents-only decision with its own switch. Raw location points are kept only as long as needed to build the day record (suggested 30 days), the record itself keeps only Places and times, never the raw track.
- Both parents: Melissa's schedule and day record live on her page, with her own calendars and her own location switch.
- Weekly review (Sunday evening, on Today): the week as a whole, hours by activity and by business vs personal, open questions, anything unusual. One tap to confirm the week.
- Sources to confirm: calendars per person (Google Calendar is connected; iCloud/Apple Calendar for Melissa, school and sports calendars), how location is shared (the installed web app's own location permission is simplest; a phone app or Apple/Google location history export are alternatives), notification time.

Open questions for F3: which calendars per person; whether to start with Ryan only and add Melissa after she has seen it; the morning delivery time; how many days a question waits before folding into the weekly review; whether mileage and business-trip records should be produced automatically for taxes.

**F3 location source — decision (Ryan, 2026-10-18): Overland.** Each adult's iPhone runs Overland (free, background, continuous, posts automatically) to a dashboard endpoint with a per-person device token; minute-level coverage everywhere, no manual steps; battery cost a few percent per day with default accuracy. Apple Significant Locations and Google Timeline are not readable automatically (policy), so Google Timeline export is only an optional manual backfill. Rules: location belongs to the person; own Day page only; raw points kept 30 days, then learned places only; children opt in with a parent only; Shortcuts place-triggers are no longer needed.

### F4. Ask: the family assistant window, and a page per family member (Ryan, 2026-10-17)
In Ryan's words: "I want a window where any document or item relates to any member of the family, whether for schedule or anything else needed. Not sure if this needs an AI API connection or just an LLM connection, but I need a personal assistant window that can answer questions and deliver documents regarding managing family life. If an API isn't available, the asked question should open the chosen LLM, and the system should copy and paste it into the prompt window of the chosen LLM app."

How it lays out (two parts: the Ask window, and the Family pages it draws on):
- Ask window: a question box on every page (and its own Ask page with history). Type or speak a question in plain words: "When is Lorynn's next dentist appointment?", "Send me the kids' insurance cards", "What did we pay the roofer last year?", "Is anyone free Saturday afternoon?", "Where's the car title?" The answer appears in the same window: a sentence, a list, a schedule block, or a document delivered as a link (opens behind the owner's unlock) or sent to the person's phone. Suggested questions appear under the box based on the day (e.g. before a trip: "What documents do we need?").
- What it knows: everything the dashboard already holds, which is the point of building the rest: calendars and the day record (F3), tasks and email summaries (F1), money records and receipts (F2, F7), the Documents finder index (names, locations and dates of every document in Organized, 1Password item names but never their contents), the family pages (below), Places, activity checklists (F6), the Log, and the Project docs and decisions log. It never reads outside this set without saying so.
- How it answers: with an AI connection, the dashboard sends the question plus only the relevant records (names, dates, links, summaries, never credentials or ID numbers) to the model and shows the answer, with "where this came from" under it. Answers that would change something (book, send, pay, file) become a task or an action card for confirmation, never an automatic action.
- Fallback when no AI connection is set up: the Ask box builds the full prompt (the question plus the relevant context it is allowed to share), copies it to the clipboard, and opens the chosen assistant app (Claude, ChatGPT, or another; chosen in Settings, per person). On phones where paste-into-app cannot be automated, the prompt is shown with a one-tap Copy and the app opens next to it. The person pastes, reads the answer there, and can paste the answer back into the Ask window to record it. Which mode is active is shown in Settings; the fallback never sends anything on its own.
- Family pages (the "window per member"): one page per family member (Ryan, Melissa, each child), each with the same sections: Today for them (their schedule and what they need today), Activities (their recurring activities with base checklists, F6), Documents (everything that relates to them: 1Password links for ID, insurance card, registration and other sensitive items; Organized links for school and medical paperwork, forms, records; links only), People and places (doctors, school, coaches, friends' parents, with contact links), Dates (birthday, renewals, appointments, recurring activities), Money (anything tagged to them: tuition, activities, allowance if set), My devices (F10, short list with a link to the register), Health (F11, private to the person; children's visible to parents), Notes (things to remember about them that the assistant can use), and Open items (tasks and questions about them). Items are tagged to a member automatically when filed (a receipt from the orthodontist tags the child it names; a calendar event with their name tags them) and can be re-tagged with one tap.
- Children's own pages (from the earlier plan) are a filtered view of their Family page: parents choose which sections a child can see.
- Delivering documents: "deliver" means the link opens the file from Organized (or the 8TB mirror), with the person's own unlock. The assistant can also attach a document to a task or an email draft (F1) when asked, and can send a document to the person's phone for showing at a counter (insurance card, registration). Nothing sensitive is stored on the dashboard itself.
- Learning: every question answered well is remembered as a pattern; every "that's not what I meant" correction improves the index (a document re-tagged, a name added as an alias). Common questions become one-tap shortcuts on the Family page.
- Ask also changes things (Ryan, 2026-10-18): the box takes instructions as well as questions. "Add [Child 1]'s new medication, 5 ml twice a day, from Dr. Smith" lands in that child's Health section; "add the Sienna's oil change today at 98,600 miles" lands in Vehicles; "add Grandma's birthday June 3" in People and dates; "turn off meal planning for me" in My dashboard; "add our new dentist" in Contacts; "stop telling me about rain" in Notifications. The system works out which setting or register the instruction belongs to, fills in what it can, and shows a one-line confirmation card before saving: what it understood, where it will go, and anything missing ("Which child?"). One tap saves; the change appears in Settings and Info at once, with the Ask instruction recorded as the source in the Log, so it can be found and undone. If the target is ambiguous it offers the two or three likely places; if the instruction would change access, money set-up or another person's settings, it saves only after that person's or a parent's confirmation (the same rules as editing Settings by hand). Sensitive entries (health) go only to the asker's own section or a child's, never to another adult's. When something is missing or unclear, Ask answers immediately in the box, like a chat (Ryan, 2026-10-18): "Is this a document, an appointment or a bill? And which child?" The person answers in words or by tapping the suggested buttons; Ask asks only for what it cannot work out itself, one or two things at a time, then shows the confirmation card and saves on a tap. The thread stays open on the Ask page, showing what it is waiting on, until it is finished. Without an AI connection the box still collects the missing facts with fixed questions (which child, what date, which account) before saving. Only a thread left unanswered for a day becomes an Inbox item, with the whole conversation attached: the person's exact words are kept with a timestamp and what was understood; the item offers its best guesses as buttons ("File a document", "Add an appointment", "Add a bill", "Something else") or asks the one missing fact; answering it reopens the thread where it left off and one tap finishes it through the normal confirmation card; it never expires, and after a few days it folds into the weekly review ("2 things you asked for that I couldn't place"); every resolution becomes a rule. Instructions are never guessed at when unsure, because a wrong save (a medication on the wrong child's page, a bill in the wrong entity) would go unseen.

Open questions for F4: which assistant Ryan and Melissa each want as the chosen app for the fallback; whether the Ask window may read email bodies (not just summaries) when answering; which sections children can see of their own pages; whether grandparents or a caregiver should ever get a limited login.

### F5. Weather-aware: always prepared, never nagged (Ryan, 2026-10-18)
In Ryan's words: "I want the dashboard to be weather conscious so it always knows the activities, the weather, and recognizes what may be needed clothing-wise or gear-wise, and a notification which will make the user constantly aware of the weather for the day's activities. I don't want it annoying but useful, so as to always be prepared."

How it lays out:
- Weather lives inside the schedule, not as a separate widget. Every block on the morning schedule (F3) carries the forecast for its time and place: temperature, rain or snow chance, wind, sun, and a one-line note. The place comes from the event or the learned Place; the time from the block. An event in another city uses that city's forecast; a trip shows the destination's weather for each day.
- Weather items on the checklist: the weather adds items to the activity's checklist (F6): rain jacket, umbrella, sunscreen, hat, gloves, layers, snow boots, a change of clothes for kids, windbreaker, water in heat. They appear in the block's "Today" layer, marked with a small weather icon, only when the forecast calls for them.
- Morning summary: the daily schedule notification (F3) opens with one weather sentence for the day that covers the activities, not the whole sky: "Cold start, 34°, warming to 58. Rain from 3 pm during pickup and practice. Bring: jackets for the kids, umbrella." If the day's weather changes nothing, the sentence is one line and there is no Bring.
- Change alerts (the only other weather notification): sent only when the forecast changes enough to change what to bring or do, for an activity in the next 12 hours (rain now expected at practice; a storm warning during the drive; temperature drop of a set amount; air quality or snow that affects an outdoor plan). One notification per change, timed so there is still time to act (default 2 hours before the block, never during quiet hours unless it is a safety warning). The same change is never sent twice.
- Pre-trip and night-before: for a trip or an unusual outdoor event, a note the evening before with the forecast and the packing list (F6). For a normal day, nothing the night before.
- Where it shows: on each schedule block; on each future event on the Calendar page (so a glance at next week shows the rain day); on the Family pages ("Today for them" shows what each child should wear or take); in Ask ("Do the kids need coats tomorrow?").
- Family-aware: each person gets their own notes for their own schedule. A parent's morning summary includes the children's activities and what the children need, so one person can get everyone out of the door. Who receives which child's notes is set in Settings (default: both parents).
- Learning: the system learns per person what counts as cold or hot (one person's "jacket weather" is another's shorts), and which alerts were useful (tapped, acted on) versus dismissed. Dismissed alert types get rarer; "always tell me about X" and "never tell me about Y" are one-tap settings on any alert.
- Controls (Settings): notification time for the morning summary; quiet hours; change-alert threshold (sensitive, normal, only big changes); units; which family members' activities to include; a "weather off" switch per person.
- Sources: a forecast service with hourly data by location (to choose at build); Places (F3) for where; calendars for when; checklists (F6) for what.

Open questions for F5: morning summary time (same as the schedule or separate); whether change alerts should go to both parents or only the one on duty for that activity; the temperature and rain thresholds to start with; whether the children's pages show their own "wear today" line.

### F6. Activity checklists: what to take, learned over time (Ryan, 2026-10-18)
In Ryan's words: "Expanding on the items list beyond weather, I want the system to generate an items checklist for each activity, be able to add and subtract items for those activities, and have it learn."

How it lays out:
- Every activity has a checklist, not only weather-driven ones. An activity is a recurring kind of event tied to a person and usually a Place: soccer practice, piano lesson, school day, swim meet, church, the workshop, a client visit, a flight, a camping trip, a doctor's appointment, a day at the beach house. The first time an activity is seen (from a calendar event or a learned Place), the system drafts a starter checklist from what it knows about that kind of activity and that person, and marks it "draft, confirm or edit".
- Three layers make up the list shown on a schedule block: Always (the base list for that activity: cleats, shin guards, water bottle), Today (added for this occasion: weather items from F5, a permission slip due, cash for the fee, a document for the appointment, a gift for the party), and Done-before (one-off items the person added for a past occasion that might apply again; shown greyed, one tap to include).
- Add and subtract: on any block, "+" adds an item (typed, spoken, or picked from recent items); swipe or tap removes one. Each change asks a tiny question only when it matters: "Remove from this time only, or always for soccer?" Default is this time only; "always" updates the base list. The same on the Family page, where each person's activities and their base lists can be edited in one place without waiting for the next occasion.
- Checking off: items can be ticked as packed; a block shows "4 of 6 packed"; the morning summary (F3/F5) mentions only what is still unpacked for the day's first activity. Ticking is optional; an unticked list is never nagged, it simply stays visible.
- Learning: items added for the same activity twice become part of Always (after a confirming tap). Items removed twice are dropped from Always. Items never ticked are offered for removal in the weekly review. Seasonal patterns are learned (shin guards all season, gloves only when cold). What one child needs for soccer seeds the draft for a sibling's new soccer activity, clearly marked as a draft.
- Shared and per-person: a family event (a trip, a picnic) has a shared list plus a per-person list; parents see all, children see their own list on their page and can tick items if parents allow.
- Where it shows: on each schedule block (collapsed to "Bring: 3 items", expands on tap); on the Family page under each activity; in Ask ("What does Lorynn need for swim tomorrow?"); in the pre-trip note the evening before (F5); and as a printable or shareable list for a trip.
- Not a nag: no notification exists only for a checklist. Lists ride along with the morning summary and the change alerts that already exist.

Open questions for F6: whether to pre-load common activity lists (sports, school, travel, medical) at setup or let each one start from the first event; whether children can edit their own base lists or only tick; how long an unused "Done-before" item stays before fading out.

#### Records it keeps (the knowledge layer behind the page)
- Accounts register: one row per account (kind, institution, last four, owner, entity, opened, statement close day, due day, autopay, where the login lives: vault item name only, both names on the account, contact method, notes). Adding a row is how an account joins the system; a charge from an unknown account creates an ask, never a silent row.
- Transactions ledger: every posted transaction from Tiller plus manual cash entries; status (matched with receipt, classified without receipt, unknown, personal, transfer, refund pending, disputed, reimbursable); category; entity; who; receipt link; notes; reconciliation id (which statement it was closed in). Tiller's own columns are never changed; the dashboard adds its own columns in the sheet and keeps a copy in its database.
- Receipts and documents: every receipt, invoice, bill and statement filed under Organized/Personal/Documents/Finance (or the business's 01_Admin/Finance) by year, with the ledger row pointing at it. Statements kept as PDF, one per account per period.
- Budget: categories and monthly limits per person and household, agreed with Melissa; business budgets per entity if wanted; versioned so last year's budget is still readable.
- Rules: merchant to category/entity, sender to document type, recurring charge to register row, "always personal" and "always business" rules, split rules (shared costs split between entities or people). Every rule shows where it came from and can be turned off.
- Vendors and payees: name, usual entity and category, usual amount, how paid, contact, 1099 flag for business vendors, W-9 on file link.
- Reimbursements and owed: who owes whom (a personal card used for a business expense, a friend's share of a dinner, a business paying a personal bill), with status until settled.
- Income: paychecks, distributions, client payments, rental income, interest, refunds, each matched to an expected amount and an invoice or statement where one exists.
- Decisions log (append-only) and Change Log (two-party acknowledgement) as already designed.

#### Reconciliations (the loops)
- Daily: pull new transactions (Tiller), match receipts (F2 search order), classify, flag. Output: the Needs me list and the morning money line in the schedule notification only when something needs a person.
- Credit cards, monthly close per card: when the statement arrives (email PDF or download), the close runs: 1) statement lines compared to the ledger for that period, every line accounted for, every ledger line present on the statement; 2) differences listed (missing, duplicate, amount mismatch, unknown merchant); 3) interest, fees and promotional terms checked and flagged; 4) payment made or scheduled is matched to the statement balance and due date; 5) every charge has a receipt or an explanation; 6) the statement PDF is filed and the close is marked done with a one-line summary ("Amex 1004: 47 charges, $3,214.18, 2 missing receipts, 0 disputes"). A close with open items stays on Needs me until resolved; it can be "closed with exceptions" by a tap that records the reason.
- Debit cards and checking accounts, monthly: same steps against the bank statement, plus: beginning and ending balance tie-out (prior ending balance plus deposits minus withdrawals equals the new ending balance); outstanding items (checks written, pending transfers) listed; transfers between own accounts matched both sides; fees and interest flagged; deposits matched to expected income.
- Savings, investments and loans, monthly or when the statement arrives: balance tie-out, contributions and withdrawals matched to transfers, interest or dividends recorded, loan payments split into principal and interest. Investments are recorded, never advised on.
- Cash: a small cash ledger per person (withdrawals from ATM become cash on hand; cash spends entered by Camera/Explain), reconciled loosely monthly.
- Payment apps (Venmo, PayPal, Apple Cash, Zelle): treated as accounts; transfers in and out matched to bank lines; person-to-person payments recorded with who and why.
- Business entities: each entity has its own ledger view, its own monthly close (P&L summary and cash position), its own vendors and 1099 tracking, and a quarterly estimated-tax reminder if applicable. Cross-entity and personal/business crossovers are recorded as reimbursements, never silently reclassified.
- Yearly: tax-year packet per entity and for the household (income, deductible categories, mileage, charitable receipts, medical if tracked, home office if applicable, 1099s and W-2s received, statements for every account for every month), checked for completeness in January; property tax, insurance renewals and registrations on the calendar; budget reset; a dedupe and archive pass over the Finance folders.

#### Automation and asks
- Automatic when confident: category and entity from rules; receipt match by merchant, amount and date; recurring charge match; transfer pairing; statement filing; reconciliation when every line ties.
- Asks (one short question each, on the dashboard): unknown merchant; receipt missing; business or personal; which entity; split; is this a duplicate; refund not received; an amount that differs from the receipt; a new recurring charge; a statement that does not tie out. Each answer becomes a rule where it can.
- Never automatic: paying, moving money, cancelling or changing a service, disputing a charge, contacting a bank. Each of those becomes a task with a prepared script or draft (F1 style) and happens only on a tap, outside the dashboard where money actually moves.

#### Notifications (few, useful)
- Morning: one money line inside the schedule notification only if something needs a person ("2 receipts missing, Amex close due Thursday"). Otherwise nothing.
- Immediate: a charge over a set amount, a charge in another country or state while the person's location (F3, if on) says otherwise, a declined or duplicate charge, a low balance before a scheduled payment, a bill due tomorrow that is not on autopay. Thresholds in Settings; both parents or one, per account.
- Weekly: the open-items count inside the weekly review (F3), with the weekly reconciliation deadline from the spending-monitor plan.
- Monthly: statement closes done or waiting, subscriptions audit (register vs reality), Change Log items awaiting acknowledgement.

#### Who sees what
- Both parents see household and joint accounts, each sees their own personal cards unless they choose to share, both see all subscriptions and the Change Log (two-party rule). Business entities visible to Ryan (and to Melissa where she has a role). Children see nothing of Money except their own allowance or activity fees if the parents enable that on their page.

#### Sources and connections
- Tiller sheet (transactions and balances for all linked accounts); statement PDFs by email (F1 filing) or downloads dropped into the financial inbox; receipts by email, Camera, Upload, bulk drop (F2); the subscriptions register sheet; manual entries. No direct bank logins in the dashboard.

### F15. Workflow review: friction found and the fixes adopted (Claude, 2026-10-18, at Ryan's request)
Method: walked each feature's daily path (wake up, handle Today, capture a receipt, answer an email, fix a wrong filing, add a medication, prepare for an activity, close a card) and looked for places where a person would hesitate, repeat themselves, or get a second notification for the same thing. Each fix below is now part of the design; the ones marked "Ryan to confirm" change something he asked for.

1. Needs me could become a long list. Six features feed it (email tasks, receipts, schedule questions, acknowledgements, vehicle and home reminders, Inbox items). Fix: one queue, one ranking. Today shows at most 5 items, ordered by due date then by effort, with "and 7 more" opening the full list. Items are tagged by effort: "30-second taps" (answer, approve, tick) sit together at the top so a person can clear them in one pass; "needs thought" (a reply, a decision with money in it) come after. Every item has Snooze (later today, tomorrow, next week). The same item is never shown twice: Money's Needs me and Today's Needs me are two views of one queue.
2. Confirmation fatigue. Rule proposals, Ask confirmation cards and two-party acknowledgements would add a tap to everything. Fix: three tiers. Low-risk changes (a checklist item, a Place name, a tag, a filing into the person's own folders, a note) save at once with a 10-second Undo, no card. Medium (a new medication, a vehicle date, a rule that will act on future items) show the one-line card. High (money set-up, access, another person's settings, anything the Change Log covers) require confirmation and, where the rule says so, both parents. Rule proposals are batched into the weekly review instead of appearing one by one, unless the same situation recurs within the week, in which case the rule is offered on the spot.
3. Learning questions could feel like surveillance or nagging. Fix: a daily cap of 3 questions per person, asked in one batch (default: with the evening or the next morning's summary), each showing the map spot and the nearest known Place first so most are one tap; a "This was private" answer leaves a gap with no follow-up; after two skips of the same pattern it is never asked again.
4. Reply drafts: opening the mail app with a draft that is missing an attachment, and relying on a red note in the first line, is a way to send a bad email. Fix: the draft lives in the dashboard until it is ready. "Open draft" opens an in-dashboard preview with inline editing; the mail draft is created in the mail app only when every attachment is present (or the person taps "Create anyway, I'll attach it myself", which is logged). "Send" then opens the finished draft in the mail app for the final send. Confirmed by Ryan, 2026-10-18.
5. Business email on family screens. Tasks from business accounts (admin@shvr.co, admin@medrepdesk.io) would mix with school forms. Fix: business-account tasks route to the Work area; Today shows one line, "Work: 4 tasks", unless an item is due today.
6. Three capture paths (the "+" button, Ask, per-item Camera/Upload) overlap. Fix: a clear split, stated in the interface: "+" is for things (photo, file, bulk drop); Ask is for words (questions, instructions); per-item buttons stay only where the item is known. A photo dropped into "+" is read and routed automatically (receipt to Money, label to Health, serial plate to Devices, form to Inbox), with the same confirmation tiers. Voice goes into Ask.
7. Small links clutter cards. "Open in …", "Sync now", "Why", "Undo", "Snooze" on every card would fight the clean principle. Fix: each card has one "…" control holding Open in source, Sync now, Why this is here, Undo, Snooze, Never show this. Cards show only their title, origin line and primary actions.
8. Two money cadences. The spending plan has a weekly receipts deadline; F7 has monthly statement closes. Fix: stated as one rhythm: daily match, weekly "receipts done" (Sunday, inside the weekly review), monthly "close" per statement. Nothing else is scheduled.
9. Navigation: twelve sections but five tabs on a phone. Fix: the bottom bar is Today, Tasks, Money, Family, More; the Calendar is reached from Today's schedule ("Full calendar", swipe left for tomorrow) and from More; Vehicles, Inbox, Recurring, Documents, Log and Settings live under More, which is a simple list, not a second dashboard. Each person can promote one More item to the bar in My dashboard (for Melissa, perhaps Calendar).
10. Settings sprawl. Eight groups plus Info is a lot to browse for one switch. Fix: a search box at the top of Settings and Info; and Ask is the primary way to change a setting ("turn off rain alerts"), so browsing is the exception.
11. Notifications could stack up from six features. Fix: a notification budget, as a rule: one scheduled notification a day per person (the morning summary, which carries schedule, weather, checklists still unpacked, the money line, vehicle and home reminders due, and the question batch if set to morning), one weekly (the Sunday review), and immediate ones only for safety and the money thresholds. Everything else waits for the morning.

### F16. Messages: a reflection of each person's own Messages threads, never a second channel (Ryan, 2026-10-18)
In Ryan's words: "I want a messages area where family communication is housed, synced with Apple Messages. Should any message sent in the app also be sent via Messages to avoid overlap or underlap? We have individual threads between each parent and each child, plus a group thread with everyone. Should the dashboard's messages section just be a reflection of the threads in the Messages app? Tell me what's possible."

What is possible with Apple Messages (facts that shape the design)
- There is no public interface to iMessage. No app can read or send iMessages on an iPhone on anyone's behalf.
- On a Mac, Messages keeps its threads in a local database that a program on that Mac can read (with Full Disk Access granted once), and a script on that Mac can send a message from the account that Mac is signed into. So a Mac can mirror and send for exactly one person: the one signed in.
- The Mac mini is signed in as Ryan, with Messages in iCloud, so it sees Ryan's threads: the family group thread and Ryan's one-to-one threads with Melissa and each child. It cannot see Melissa's one-to-one threads with the children.
- Melissa's MacBook Air can run the same mirror for her threads, signed in as her. The children's phones are not mirrored; parents see the children's messages only through their own side of each thread, which is what they already see in Messages.
- A message sent from the dashboard is sent by that person's own Mac as that person, so it appears in Messages for everyone exactly like a message typed in Messages. That is what removes overlap: there is only ever one conversation, in Messages, and the dashboard is a window on it.
- Limits: the mirror needs the Mac awake (the mini is always on; Melissa's laptop only when open, so her mirror catches up when it wakes); it depends on Apple not changing the database layout (a macOS update can break it until the reader is updated; the dashboard shows "Messages mirror paused" rather than failing silently); the Mac mini already does the same kind of local work for backups, so this fits its role.

Decision recommended: the Messages section is a reflection of each person's own threads in Messages, read and written through that person's own Mac, plus what the dashboard can add on top. No dashboard-only messaging. If a thread exists in Messages, it appears; if it does not, the dashboard does not invent one.

How it lays out:
- Messages page (under More; a "Family" line on Today only when a family message needs the person): the family group thread first, then the person's one-to-one threads with family members, each showing the latest line and unread count, as in Messages. #### F18 appendix: when an API call happens, and when it does not (Ryan asked for the parameters, 2026-10-18)

Never an API call (local, no cost)

- Filing a document that matches an existing rule; tagging a file to a family member when the name match is exact.

Haiku calls (cents per hundred; the small ones)
- A new email arrives that no rule covers: decide task-or-not, type, who, due date. Roughly 100 a day at first, far fewer once senders have rules. Example: a first message from a new orthodontist's office.
- A receipt or statement line that amount and date cannot match on their own: pick among candidates. Example: two charges at Costco the same day.

- A family message that might contain a request: "can you pick me up at 4" becomes a proposed task. Each mirrored family message is screened once.
- Deciding whether an Ask or text input is a question, an instruction, or structured (so it can be routed locally next time).
- Tagging a document to a family member when the match is not exact.
Cost sense: at $0.10 per million input tokens, 100 emails a day is about three cents a day.

- The morning summary when judgement is needed (several things compete; what goes first). On a plain day the template version runs locally and costs nothing.
- The Sunday weekly review synthesis (one call per person per week).
- "Why is this here" explanations, proposing a rule in plain words, the confirmation card text for a medium-tier change.

Cost sense: a typical exchange is a cent or two; a long document question five to ten cents.

Opus calls (rare, logged with the reason)

Cost sense: ten to thirty cents each; a handful a month.

Deflections (out of scope): the "is this related to managing the family?" check is one small Haiku call; a plain deflection after a "no" costs nothing further.
